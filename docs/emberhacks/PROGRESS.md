## README draft (from B, 14:04 — for A/C2 to paste; numbers are from PROGRESS rows B0–B7)

### How Gemini is used
Three models, three jobs, all through code that is the trust boundary (gate → validator → IK pre-check before anything moves):
- **gemini-3.8-live** — ears and voice. Hold-to-talk 16 kHz PCM in, 24 kHz audio out, voice "Kore", function calling for run_task (NON_BLOCKING, answered at once; completion arrives later as a spoken `[CELL EVENT]`), create_object, point_at, describe_scene, cell_status, cancel_task, remove_object. Automatic activity detection is off (the TALK button is the turn), context-window compression on. Gemini cannot stop, resume or reset the cell; gestures always win.
- **gemini-robotics-er-2-preview** — eyes and planner. Points at every part on a rendered 768² cell-camera frame (error vs the registry ground truth is measured and shown in mm — typically 1 mm on the table, ~11 mm inside the tray), plans with function calling (pick / place_in_tray / place_at / move_to / open_gripper / close_gripper / home / done) at thinking level HIGH (measured 1.1–1.4 s), acts at LOW, and verifies every pick/place/home from a fresh frame at LOW ("The red block is resting inside the blue tray and the gripper is open above it."). Disagreements between the code verdict and ER's are shown as DISAGREE lines, never hidden. A grasp-feasibility check (MEDIUM) runs on every part created by voice or text.
- **gemini-3.8-flash** — the same coworker over typed text (same tools, same system prompt) and the fallback planner if ER-2 is unavailable. Never ER-1.6 (deprecated, 404).

Measured (B0 smoke and G3 runs): typed "put the red block in the tray" end to end 20 s, 6 model calls, $0.015; pointing error 1 mm; plan HIGH 1.1–1.4 s; function-response shape A (frame inside `functionResponse.parts`) validated; `responseJsonSchema` on for pointing. DEMO_MODE = { consensusN: 1, planLevel: HIGH, fcShape: A, pointSchema: true, maxIdenticalFailures: 3 }, toggles in the Coworker pane.

### What leaves this machine
Gesture recognition stays on-device (MediaPipe). While a voice session is connected and TALK is held, microphone audio streams to Gemini Live; rendered cell-camera frames go to Gemini Robotics-ER during tasks (and one frame per created part for the grasp check). Webcam frames never leave this machine in this build. Nothing is recorded by this app. The counters in the top bar ("LEAVING THIS MACHINE · mic ● / ○ · cell frames N · webcam frames 0") show exactly what has left, and the export JSON lists every Gemini call with latency, tokens and cost.
